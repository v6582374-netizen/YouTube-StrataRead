# YouTube 阅读文档

YouTube 模块自动获取用户订阅更新并生成阅读文档。主页面直接呈现已生成的文档，不要求用户理解收件箱、队列或模型路由；生成中的工作、失败和选择性取消集中在 YouTube 内的独立“处理进度”页。页面默认展示任务概览，事件时间线按需展开；“自动更新”入口直达该页。模型未就绪时才提供必要的设置入口。

## 同一份资料库的三个视图

时间流按视频发布日期分组；文档库强调标题、正文摘录与估算阅读时长；频道索引以来源导航组织文档。三者使用同一份查询结果、时间／频道／未读筛选和文档操作。视图偏好保存在本机，切换不清空筛选或修改资料。

页面沿用 Edison 的字体、字号、色彩和明暗材料变量。选择器位于筛选栏右侧，键盘可达、具有明确标签。高频筛选与视图切换即时响应，不加等待动画。

## 视频基础信息

视频条目服务于内容取舍：让人判断来源、内容新旧和视频体量。订阅发现、处理进度、阅读库中的视频条目统一呈现频道、YouTube 发布时间与视频时长，标题继续作为主信息。各页面按自身用途补充处理状态或失败原因。

“发布时间”指视频在 YouTube 上的发布时间，不以 Edison 发现、获取或刷新时间代替，也不表示标题等信息的最后修改时间。“视频时长”指源视频播放长度，与文稿估算阅读时长分开。首轮范围不加入播放量、点赞数或视频简介。

展示示例：`a16z · 发布于 2026-09-18 · 视频 42 分 18 秒`。阅读库保留单独标注的“预计阅读 12 分钟”；处理进度页只显示视频时长。

后续新发现的视频应在正常元数据获取流程中获取并保存源视频时长，供各视图一致展示。不要求所有条目立即拥有时长；元数据获取遵守既有 YouTube 共享冷却，缺失时长不阻塞页面或文稿处理。

不建设历史视频时长补齐机制，也不因浏览旧条目触发历史补齐。用户计划在正式发布前清空视频条目，因此验收以新发现视频的信息正常保存和展示为准；清空数据属于独立发布操作，不在本次功能范围内。

缺失字段明确显示“发布日期未知”或“时长未知”，只有实际正在获取时才显示“获取中”。不以本地时间替代发布日期，不将未知时长显示为零，不增加逐条修复按钮。

实现已覆盖发现结果、处理队列、当前处理视频、阅读库三个视图及详情面板。视频时长复用正常字幕获取流程中的 YouTube 元数据请求，并在字幕下载前保存；字幕不可用或随后失败不丢失已取得的时长。尚未进入元数据获取阶段的新视频显示“时长未知”。验证结果见 [视频基础信息交付记录](youtube-video-metadata-delivery.md)。

## 订阅与生成规则

默认处理全部订阅。用户明确排除的频道会持久化；未在排除名单的新订阅默认开启。同步订阅导入最新列表，连接成功后立即唤醒更新发现。

排除频道阻止新的发现和队列领取，正在处理的文档会完成，已有文档不会被删除。恢复频道后，其保留的待处理更新可继续生成。排除不是历史文档的隐藏筛选。

Prompt 在独立对话框编辑并显式保存到资料库。空内容拒绝保存；取消不写入；恢复默认规则仍需点击保存。每次生成开始时读取已保存规则，修改不会改变已开始的调用或覆写现有版本。模型与凭据继续使用 Edison 全局设置。

## 文档交接

选择文档打开紧凑的信息面板：来源、发布日期、定时字幕、版本与阅读标记；不自动启动外部应用，也不内嵌长文阅读器。正文可复制，文件可用 macOS 默认应用打开。重新生成创建新版本；删除需明确确认。

主文档查询以“已有稿件”为准，所以重新生成期间旧版本仍可查阅。既有阅读状态保留兼容，界面统一显示已读／未读。
